## Требования:

- Ровно n worker goroutines.
- Submit не создаёт goroutine на каждую задачу.
- Очередь ограничена размером 100.
- Если очередь заполнена, Submit должен ждать свободного места либо вернуть ctx.Err().
- Shutdown() прекращает приём новых задач.
- Уже принятые задачи должны быть обработаны.
- После завершения всех задач Shutdown() должен дождаться завершения workers.
- Если Shutdown(ctx) получает cancelled context, он возвращает ctx.Err(), но сам Pool продолжает корректно завершаться.
- Submit() должен быть safe для одновременного вызова из сотен goroutines.
- Нельзя использовать errgroup, внешние worker-pool библиотеки и sync.Cond.
- Нельзя допустить panic из worker-а, который оставит WaitGroup навсегда зависшим.
- Нужно корректно обработать повторный вызов Shutdown().

И отдельный подвох: Submit() должен быть защищён от гонки с Shutdown(), 
например когда одна goroutine почти одновременно делает Submit(job), а другая Shutdown(ctx).
